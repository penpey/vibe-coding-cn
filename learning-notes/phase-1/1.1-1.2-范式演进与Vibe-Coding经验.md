## 核心要点

1. 软件开发范式是**随复杂度递进的**，不是线性替代——五层并存，按需组合
2. Vibe Coding 是第六层：不改变代码组织方式，改变**谁来写、怎么协作**
3. 人机分工铁律：**人负责目标/约束/判断/验收，AI 负责执行，机器门禁负责拦截**
4. `AI 不能自证正确`——所有规范必须变成机器门禁，不能只写在提示词里
5. 入门铁律：先定义问题 → 先要计划 → 每步可验证 → 频繁 Git 提交

---

## 关键概念

| 概念 | 解释 |
|:---|:---|
| 范式 | 一套组织代码/系统的思想框架，不是语言，是"怎么想问题" |
| 机器门禁 | 用 lint/test/CI/schema 等工具强制执行规范，不靠人记住 |
| 四层能力 | 连接（CLI）→ 读写（文件操作）→ 闭环（命令执行）→ 复用（沉淀经验） |
| 入门铁律 | 8 条不能违反的基本原则，违反任何一条都会导致 AI 协作失控 |

---

## 五个范式层

```
1. 面向过程    → 按步骤/函数组织，强调顺序性
2. 面向对象    → 数据+行为封装为对象，强调复用性
3. 面向接口    → 依赖抽象不依赖实现，强调可替换性
4. 组件化/分层 → 职责明确的模块，强调可组合性
5. 服务化/云原生 → 独立部署的服务单元，强调弹性
6. Vibe Coding → 人+AI协作，强调可验证的工程产物
```
